# 菌丝 Mycelium

**▶ 在线试玩：<https://liuyuling528-oss.github.io/mycelium/>** —— 不用下载，打开就能玩

> 一个**增量放置**（incremental / idle）游戏。引擎：**Phaser 3.80**。
> 因为之前的 Excel VBA 版本束手束脚（没有实时循环、连粒子都画不了），改用真正的游戏引擎重做。

**题材**：森林地表下的**菌根网络**（mycorrhizal network，也就是科普里的 "Wood Wide Web"）。
你是落在土壤里的一粒孢子，向四周蔓延菌丝、吸收落叶与腐木的养分、沿水脉取水、连上树根结出孢子。
养分耗尽时散播孢子、重开一轮 —— 这在生物学上是真实发生的（黏菌与真菌确实会形成子实体并释放孢子）。

极少数放置游戏用过这个题材，而它天然带**空间决策**，这正是上一版最缺的东西。

![游戏画面](art/gameplay.png)

> 白色是被你养起来的菌丝网络，金色是孢子落点（核心）。
> 蓝/紫色半透明大圈是事件增益区，红色标记是被害虫占据、已经停产的节点。

## 怎么玩

**双击 `index.html` 即可**。Phaser 已内置在 `vendor/`，不联网也能跑。

- **点击带圆点提示的空格**就能蔓延一格菌丝，**金色脉冲框**是当前策略推荐的那一格
- **点击已有的菌丝**可以**强化**它（消耗养分，同时提升产出和吞吐）—— 这是「深耕流」
- **点击红色的害虫**把它驱除掉
- 地图上的颜色就是底下的东西：**棕色=落叶层**（产养分）、**深棕=腐木**（养分最高）、**蓝色=地下水脉**（产水）、**绿色=树根**（产孢子）、**深灰=岩块**（长不进去）
- 蓝/紫色的半透明大圆是**事件增益区**（区域内对应资源 ×3）—— 值得专门绕路去吃掉它
- **按 1 / 2 / 3 放技能**

### 屏幕适配

- **桌面（宽）**：左边地图铺满剩余空间，右边面板独立滚动，地图永远钉在视口里。
- **窄屏 / 手机**：单列，地图 **sticky 在顶部**，整页滚动 ——
  一边看网络一边改策略，不用来回滚。高度用 `svh` 而不是 `vh`，
  地址栏收起/展开时地图不会跳。
- **地图会自动取景**：视野对准「已探明区域 + 一点余量」，网络长大了镜头缓缓拉开，
  始终铺满画面而不是缩在一角。缩放有两个硬约束：
  不大于每格 46px（否则开局那几个格子会被放成马赛克），
  不小于「整张地图刚好装下」（**绝不裁掉网络的任何一部分**）。
- **触摸有 1 格容差**：手指点偏一格时自动落到旁边可操作的格子；
  鼠标不启用容差，桌面行为完全不变。

### 手势与镜头

| 操作 | 效果 |
|---|---|
| 滚轮 | 以指针位置为锚点缩放（指哪放大哪） |
| 按住拖动（单指 / 鼠标） | 平移视野 |
| 双指捏合 | 缩放 + 双指平移（手机标准手感） |
| 右上角 ⟲ 按钮 | 回到自动取景（镜头重新跟着网络走） |

设计要点：

- **点击与拖拽的判定放在「抬起」时**，位移超过 6px 就算拖拽。
  如果按下就执行，拖动一下就会顺手长出一格。
- **手动缩放/平移会停掉自动取景** —— 否则每帧的自动缓动会把你刚拖到的位置
  立刻顶回去，用起来像镜头在跟你抢。右上角 ⟲ 随时交还给自动取景。
- 缩放范围：不小于「整张地图刚好装下」×0.85，不大于每格约 62px；
  平移中心始终夹在世界内，**拖不丢**。
- 捏合期间按下的手指，抬起时**不算点击**。这里不能用「时间窗」做冷却：
  冷却走的是游戏时间，rAF 一停（切后台、headless 帧稀疏）时间就不走了，
  窗口永远不过期，用户回来之后怎么点都没反应 —— 实测踩过，已改成按指针登记。

### 转生换图

每次转生（散播孢子）都会生成**一张全新的地图**，而且**比上一张更大**：

- 尺寸阶梯：边长 = 基础 34×20 × `min(2, 1 + 0.12 × 转生次数)`，最多长到 68×40（面积 4 倍）
- 新种子由旧地图**确定性推出**（不能用 `Math.random` —— 平衡对照模拟靠
  「同种子 → 同地图序列」比较策略，一随机每次跑出来的结果就不可比了）
- 代价：上一张地图的探索记录作废（换图前记得看一眼，收益换成了更大的世界 + 基因）
- 地形特征（矿脉/岩石/腐木）数量按**面积**缩放，密度不变 —— 大地图不会变成空地
- 经济封顶在面积 4 倍：孢子收入正比于节点数，地图无上限就等于经济无上限

实现上顺带修了一个老 bug：**读档从来没把探索记录应用回网格** ——
读档后已探明区域会整个消失，只剩核心周围一圈。现在 `deserialize` 会正确恢复。

### 四个动作，不是两个

早期版本只有「点格子」和「买升级」两个动词，点完就只能等，玩起来很快就平。现在每时每刻都有事做：

| 系统 | 作用 |
|---|---|
| **节点强化** | 让「点击」有两个用途：长新格子 / 练老格子。等级光环一眼看出深耕在哪 |
| **主动技能（1/2/3）** | 菌丝脉冲（8 秒蔓延 ×4）、酶解（立刻结算 30 秒养分）、孢子爆（孢子 = 菌丝数×1.5）。带冷却，制造「攒时机 → 一波爆发」的节奏 |
| **地图事件** | 降雨带 / 孢子季（区域内产出 ×3，值得绕路）、害虫（占据节点使其**停产**，点掉它还有养分奖励） |
| **里程碑（8 条）** | 渐进解锁，避免一开局就把所有东西摆在眼前 —— 那是「内容很多但很平」的常见死因 |

**事件全部是正面或中性的**：忽视只会错过一笔收益，绝不造成永久损失。
放置游戏的玩家一定会离开，惩罚性设计会让「回来一看全毁了」直接劝退。

### 三条真正需要权衡的规则

1. **资源必须沿菌丝运回核心，路越远越亏**
   每格距离损耗 5.5%，20 格外的效率只剩 48%。所以「近处的贫瘠壤土」和「远处的富矿」是真取舍。「运输效率」升级就是在把远处的富矿变得值得修路。

2. **拥堵**：每个节点有货物吞吐上限，超了只有 30% 挤得过去（软上限）。
   面板上的「拥堵损耗」就是升级「菌丝加粗」的信号。**堆产能升级会加剧拥堵，必须搭配加粗。**

3. **孢子 = 网络规模**：每个节点都微量产孢子，树根是加速器。
   这是刻意的设计 —— 保证**扩张永远有收益**（增量游戏的根本）。

### 转生：散播孢子

攒够孢子就能散播。菌丝网络全部重来，但**已探明的地图永久保留**，并换取**基因点**买永久天赋。
这就是放置游戏的引擎：一轮比一轮快。

## 文件结构

```
index.html              入口（双击即玩）
style.css               右侧面板样式

src/config.js           ★ 所有平衡数值都在这里，改它就能调游戏
src/rng.js              确定性随机 + 噪声（同一颗种子永远是同一张地图）
src/sim.js              ★ 核心模拟层：地图、资源链、运输、升级、转生（纯逻辑，无渲染）
src/scenes/WorldScene.js  地图渲染与交互（Phaser）
src/ui.js               右侧 HTML 面板与状态的桥接
src/main.js             启动、存档（localStorage 自动存）

tools/headless_sim.js   ★ 离线平衡模拟（Node 直接跑，不用浏览器）
tools/autotest.js       浏览器端自测钩子（只在 ?autotest=1 时生效）
tools/viewport-probe.html  窄屏探针：在 iframe 里以真机宽度跑自测（见下文）
vendor/phaser.min.js    Phaser 3.80.1（已内置，离线可用）
art/gameplay.png        游戏截图
LICENSE                 MIT
```

UI 用 **HTML/CSS 面板 + Phaser 只渲染地图**：列表、下拉框、滚动条交给浏览器，
比在 canvas 里画文字好得多，代码也短得多。

## 改完一定要验证（这是这个项目最重要的约定）

### 1. 数值平衡 —— 必须先跑这个，再动渲染层

```bash
node tools/headless_sim.js 1800      # 模拟 30 分钟
```

它会跑 6 种策略 × 5 个种子并给出结论。**通过的判据是策略必须真的产生差异**：

```
✅ 策略差异 6.13 倍 —— 决策是有意义的。
✅ 主动点击收益是挂机的 1.55 倍 —— 注意力有价值。
· 拥堵损耗占产出 29.4%
```

**为什么这个脚本必须存在**：上一版 Excel 游戏我做了 25 项测试全绿，却全是「不崩、能跑、数值不发散」的工程正确性测试，
**没有一项在验证「玩家的决策是否影响结果」**。结果玩家花不花钱，最终都停在同一关。
那个教训就是：**做游戏要先跑「不同策略 → 结果是否有差异」的对照模拟，差异为 0 就是设计失败。**

调数值时它还抓出过两个结构性错误（都是它先发现、我才改的）：
- 节点强化成本增速设成 1.55 时，玩家把养分全砸节点就能碾压其他所有路线（强 3.3 倍）——
  **最优解唯一等于又变回无聊**，所以改成 1.72 让边际递减。
- 吞吐上限一开始设成硬上限，导致 94% 产出被浪费、「扩张反而没收益」。

### 2. 浏览器端 —— 端到端自测

```bash
python -m http.server 8321
chrome --headless=new --virtual-time-budget=60000 \
       --dump-dom "http://127.0.0.1:8321/index.html?autotest=1"
```

**69 项断言** → 加入手势与转生换图后现在是 **95 项**，覆盖引擎启动、真实点击生长、
技能冷却、节点强化、里程碑发奖与防重复发奖、害虫停产与驱除、增益区倍率、存档往返、
长时间不发散、自适应布局、**滚轮/拖拽/捏合手势**、**转生换图**、零 JS 异常。

**用 http 起服务，不要用 `file://`。** file:// 下所有脚本都是不透明源，
任何异常都只会报成 `Script error. @?:0` —— 只有文件名没有行号，等于没法排查。
（这条是实测踩出来的：自测报了一条 Script error，换成 http 后立刻定位到
`ui.js` 某行读了个不存在的属性。）

### 3. 窄屏 —— 用探针，别指望缩窗口

```bash
# 真机宽度跑自测并把报告搬到顶层文档，便于 --dump-dom 读回
chrome --headless=new --window-size=1100,900 --virtual-time-budget=80000 \
       --dump-dom "http://127.0.0.1:8321/tools/viewport-probe.html?w=390"
```

**Chrome 在 Windows 上的窗口最小宽度约 500px**，`--window-size=414` 会被静默夹住
（报出来的 `innerWidth` 是 500，不是 414）；`--force-device-scale-factor` 只改渲染密度、
不改 CSS 视口。所以直接在桌面上测手机宽度是测不到的 —— 媒体查询里的窄屏规则会变成
「写了但从没执行过」。`tools/viewport-probe.html` 用 iframe 绕开这一点：
iframe 有独立的布局视口，媒体查询看的是它的宽度。

已实测宽度：**1366 / 1024 / 820 / 390 / 320**，全部 69 项通过、零异常。

**这个项目的点击测试有个硬要求**：派发事件时要把 `pointer*` 和 `mouse*` **都发一遍**
（`moveTo` / `clickAt` 就是干这个的）。Phaser 在不同环境里挂的监听不一样，
只发 `pointerdown` 时它可能收不到 —— 那样「点了没反应」这类断言会因为
**压根没收到点击**而假通过。所以自测里放了一个**正对照**（点一个本来就能长的格子，
必须长出菌丝）；正对照失败就说明后面那些「不生长」的断言全是假的。

**它抓出过一个肉眼绝对看不出来的 bug**：事件系统原本每次生成都新建 RNG
（`makeRng(seed + n)`），而 **mulberry32 对相近种子的第一个输出高度相关** ——
40 次事件判定全落在同一侧，**害虫永远不出现**，但代码看起来完全正常。
自测的「事件类型有分化」断言（`{"rain":9,"gnat":3,"bloom":8}`）就是为它加的回归防线。

**开发时踩过的坑，别再踩**：

- **Phaser 把原生指针事件排队，下一帧才处理** —— 派发事件后同步断言必然失败，必须让出一帧。
- **场景必须写 `class extends Phaser.Scene`**。用普通对象字面量传进去，Phaser 只当它是配置对象，
  自定义方法不会挂到实例上，表现是「点击地图完全没反应」。
- **这个环境里光派发 `pointerdown` 不够**，Phaser 监听的可能是 `mousedown`。自测里两种都发。
- **测试要 arrange 干净**：害虫会累积到上限（之后就再也生不出来）、里程碑奖励只发一次
  （抹掉 `unlocked` 只会得到假失败）。两次假失败都是这么来的。
- **`?demo=秒数`** 可以快速养大网络，方便截图和目视检查。

## 设计上刻意避免的两个陷阱

| 陷阱 | 后果 | 这里的处理 |
|---|---|---|
| 敌人/难度与玩家同步成长 | 相对强度恒定，玩家永远感觉不到变强 | 资源靠「距离损耗 + 拥堵」而非难度曲线；成长感来自网络拓扑 |
| 吞吐上限设死 | 扩张反而没收益，与增量游戏根本冲突 | 改成**软上限**（超载仍过 30%），并用水/货物分带宽（水不受限） |

第二条是实测发现的：早期版本让 98 个高产水脉把带宽全占满，养分和孢子运不回来，
**扩张反而把自己饿死**，94% 的产出被浪费。现在水作为生长介质自由流动，拥堵只发生在真正的货物上。
