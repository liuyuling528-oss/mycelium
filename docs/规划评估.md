# Mycelium 规划文档评估

对 `Mycelium_未来玩法拓展详细规划_v2.docx` 逐条评估。
评估基准：**当前代码现状**（2026-09-18，commit 17bab67），不是凭印象。

---

## 总评

**方向判断基本正确，但颗粒度差异极大，且有几条与现有设计冲突。**

值得肯定的三点（这三条是整份文档最有价值的部分）：

1. **「新增玩法优先改变决策，而不是单纯增加倍率」** —— 和我这边的
   `headless_sim` 判据（策略差异必须 > 0）是同一个信念，方向完全一致
2. **「负面事件造成短期压力，不永久摧毁长期建设」** —— 和我现有菌瘟/害虫的设计底线一致
3. **「避免永久唯一最优解」** —— 我这边已经在用平衡模拟守这条线
   （节点强化成本增速从 1.55 调到 1.72 就是为了这个）

主要问题：

- **19 个系统全部平铺**，没有区分「这是 3 天能做的」和「这是 3 周才能做的」
- **缺少量化**：只有「建议 8~12 小时离线上限」一处给了数字
- **与现有设计有冲突**（详见「需要警惕的」章节）
- 有几条**已经在做或已做完**（如自动化策略、平衡测试）

---

## 一、可以直接做，收益明确（建议优先）

这些是真实缺口，改动可控，且能验证。

### ★ P0-1　离线收益　— 真缺口，建议第一个做

**现状**：`src/main.js` 里**完全没有**记录离开时间，`grep offline|lastSeen|Date.now`
零命中。也就是说现在关掉页面再回来，**期间一无所获** —— 这对一个放置游戏是硬伤。

文档建议的「8~12 小时上限」是对的，还需要补一条它没说的：
**离线收益必须低于在线主动操作**。否则最优玩法变成「关掉页面等」，
主动点击的价值就没了 —— 而我现在的平衡数据是主动/挂机 = 3.20×，
离线收益的设计必须在**不破坏这个比值**的前提下做。

实现要点：
- 存档里加 `lastSeen` 时间戳（`Date.now()`）
- 上线时算 `dt`，按**离线模式**推进模拟（不能按满速跑 —— 玩家不在时
  没有点击、没有驱虫、没有防火墙，按满速跑等于白送）
- 上限 8~12 小时；上线弹窗显示「离开了 X 小时，菌丝 +N 格，资源 +M」
- **负面事件不在离线期间发生**（文档这条说对了，和我现有底线一致）

验证：`headless_sim` 加一条「离线 8 小时收益 vs 在线 8 小时主动操作收益」对照，
**离线必须明显更低**。

### ★ P0-2　自动化规则（把策略升级为规则）

**现状**：已有 5 种策略（`POLICIES`），但**只有一个开关**
（`state.policy` 单选），没有规则组合。

文档提的 7 条规则里，**「遇到岩石自动绕路」已经天然实现**
（岩块 `solid: true`，`candidates` 不会产出它）。
真正值得加的是这 3 条，因为它们能让玩家「设计网络」而不只是「选一个模式」：

1. **目标距离上限**（不超过 N 格）—— 让玩家能说「只吃近处的」
2. **收益阈值**（低于 N 不连）—— 防止自动扩张去啃贫瘠壤土
3. **发现稀有资源时暂停普通扩张** —— 这条最有策略味道，但要等有稀有资源再说

实现上不需要「规则引擎」，在 `scoreCandidate` 里加两个可选过滤条件即可 ——
**不要过度设计**（这点文档没说，但是我的经验）。

### P1-1　主干菌丝　— 目前最有价值的「网络结构化」改动

**现状**：节点强化（`NODE_UP`）是**均匀**的 —— 每个节点都能练，
练到 Lv10 的效果是「自己产出 +25%/级、自己吞吐 +18%/级」。
**没有「这条线路比那条重要」的概念。**

文档说的「把已有菌丝升级为主干」，本质是给玩家一个**作用于「线路」而非「节点」**
的升级维度。这正好补上现有设计的一个真实空缺：

现在的取舍是「深耕哪个节点」，加上主干后变成
**「深耕哪个节点 + 哪条线路值得变成主干」** —— 后者是真正的网络规划。

要注意的：**主干不能只是「更好的菌丝」**，那会变成又一个倍率升级。
它必须带代价或限制，比如：
- 主干更长更贵（升级成本按线路长度算）
- 或者「主干数量受限」（像菌落那样），逼玩家选哪条路当主动脉

建议先做**最小版本**：允许把节点标为主干，主干吞吐 ×N，
但**全网络主干节点数有上限**（比如 5 个）。然后跑平衡模拟看是否产生策略差异。

### P1-2　汇流节点

和主干天然配套：多个资源点先汇入中转节点，再走主干回核心。
**技术上是现成的** —— 我现在的运输模型已经是「沿菌丝回核心」，
汇流节点相当于给某节点加一个「汇聚」角色。

但这条**必须和主干一起做**才有意义（单独做汇流没有主干承载，收益不明显）。

## 二、方向对，但需要先解决前置问题

### 菌株系统（文档第四章）

**评估：这是整份文档最好的想法，但现在做不了。**

文档说「不应该只是简单增加 10% 资源，而应该改变玩家的玩法倾向」——
完全正确。但它列的 6 种菌株（快速生长/运输/腐木/根系共生/耐旱/发光）里，
**有 4 种依赖还不存在的系统**：

| 菌株 | 依赖的前置系统 | 现状 |
|---|---|---|
| 快速生长 | 无 | ✅ 可做 |
| 运输 | **主干菌丝** | ❌ 待做 |
| 腐木 | **地图主题/资源分布差异** | ❌ 待做 |
| 根系共生 | **树木系统** | ❌ 待做 |
| 耐旱 | **季节/干旱** | ❌ 待做 |
| 发光 | **地下层** | ❌ 待做 |

**所以菌株不是「第一个做」的，而是「主干 + 树木 + 季节都做完之后」的收口。**
现在硬做，只能做出「快速生长」一种，那不叫 Build 系统。

**建议顺序**：主干菌丝 → 树木系统 → 菌株（这时才有 3~4 种真有差异的菌株可选）。

### 树木与共生网络（文档第六章）

**评估：方向对，但要警惕和现有「树根」重复。**

现在 `SOILS` 里已经有 `root`（树根，产孢子 0.40）。文档说的「幼树/成年树/古树/枯树」
是把**一个资源格类型**扩展成**一组有生命周期的对象**。

这个升级是值得的（「连接 5 棵树解锁特殊能力」= 给地图一个长期目标），
但要小心：**不要让树变成又一个资源格**。文档自己也说了
「树木不只是资源格，而应该成为生态系统的重要节点」—— 关键是
**树要能影响周围**（比如「古树周围的菌丝产出 +X」），
那样它才是「空间决策」，否则只是「更肥的格子」。

### 季节与动态环境（文档第十章）

**评估：方向对，但这是「换汤不换药」的高风险区。**

文档自己点出了关键：「重点不是给所有资源简单乘倍率」。
说得对，但它给的四个季节描述**基本都是乘倍率**
（春季活性提高、秋季腐木增加、冬季速度下降）—— 自己没做到自己说的。

做季节的**唯一理由**应该是：**它改变地图条件，从而改变最优网络形状**。
比如「夏季部分区域干旱 → 原本的最优路线失效 → 需要绕路」。

如果做不到这一点，季节就只是「定期给玩家一个 debuff」，不加也罢。
**建议：想做季节，先想清楚「哪个季节会让我必须重新规划网络」**，
想不出来就先不做。

### 事件系统升级（文档第十一章）

**评估：方向对，但「菌群竞争」有冲突风险。**

文档建议的 5 种事件里：
- **降雨**：已有（降雨带）
- **害虫**：已有
- **腐木爆发**：可做，是现有增益区的「资源版」
- **干旱**：可做，但要小心 —— 「远端菌丝效率降低」会惩罚**已经建好的网络**，
  和我现有的「绝不永久损失」底线有张力，必须做成**短期**的
- **菌群竞争**：「某区域暂时无法继续扩张」—— 这条**技术上就是「临时岩块」**，
  可做，但要确认它不会让玩家觉得「我规划好的路白修了」

### 地下多层地图（文档第十二章）

**评估：想法好，但这是「第二张地图」量级的工作，不是「加一层」。**

文档自己也说了「当二维地图的空间玩法成熟后」。这是诚实的。
现在做等于把整个渲染、寻路、取景、平衡全部重做一遍。
**建议放到 P3，或者干脆不做**（除非二维玩法已经被证明够深）。

## 三、需要警惕的（与现有设计冲突或重复）

### ⚠️ 菌落系统（文档第八章）—— 与现有「节点强化」功能重叠

「资源菌落 / 运输菌落 / 孢子菌落 / 探索菌落」四种功能基地，
**本质上是「节点强化」的一个更复杂的版本**。

现在的节点强化已经能做到「这个节点产出高」，
菌落加进来会变成「这个节点产出高，而且还带一个标签叫菌落」——
如果菌落不能做出**新的决策维度**，它就是纯粹的增加复杂度。

**要做得有意义，菌落必须满足**：数量严格受限（比如 3 个）
+ 影响**一片区域**而非一个点（比如「资源菌落让周围 3 格内采集 +50%」）。
后者才是新的 —— 「我要在哪建菌落」是空间决策。

### ⚠️ 主干 + 环路 + 备用线路 + 汇流节点（文档第三章）—— 四个系统，建议只做两个

文档一次提了 4 个网络结构系统。**它们互相依赖且都会显著增加模拟复杂度**：

- **主干**：值得做（见上）
- **汇流节点**：值得做，但和主干绑定
- **备用线路**：「主干拥堵时建第二条」—— 但我现在的运输模型是
  **「每个节点沿最短路径回核心」**，没有「线路」这个实体，
  做备用线路需要**重写整个运输层**（引入图的流量分配）
- **菌丝环路**：「允许形成闭环」—— 同上，需要重写运输层

**建议**：先做主干 + 汇流（改动可控），
**备用线路和环路留到「确实需要」时再做** —— 它们的复杂度/收益比明显更差。

### ⚠️ 自动化规则（文档第九章）—— 不要做「规则引擎」

文档列了 7 条可组合规则，还说「高级玩家可以组合规则管理整个网络」。
**这是最容易过度设计的地方。**

一个可视化规则编辑器 = 大量 UI 工作 + 大量 bug + 绝大多数玩家不会用。
**建议只做 2~3 个开关**（距离上限、收益阈值），
放在现有策略选择器下面，**不要做规则组合系统**。

### ⚠️ 离线收益的一个隐患（文档没说）

文档说「离线期间可以计算基础生产和自动扩张」。
但要小心：**如果玩家的自动蔓延没解锁，离线期间就没有自动扩张** ——
早期玩家离线回来发现「什么都没发生」，体验很差。

需要明确：离线收益的**下限**是什么？（比如至少按核心渗水给一点）
这会影响前期体验，建议做成「即使没解锁自动蔓延，离线也有基础产出」。

## 四、已经做完或已在做的（不必重复）

| 文档建议 | 现状 |

| 平衡测试（第十八章） | ✅ 已有 `headless_sim`，但**文档的建议可以采纳**（见下） |
| 「负面事件不永久摧毁」 | ✅ 已是现有底线 |
| 「避免唯一最优解」 | ✅ 已用平衡模拟守住（1.55→1.72） |
| 图鉴（第十五章） | ⚪ 未做，但优先级低（纯收集，不改变决策） |

**文档第十八章「平衡测试」的建议值得采纳一半**：

- ✅ 「测试 10/30/60 分钟曲线」—— 现在只跑 1800s，加长时间维度成本很低
- ✅ 「测试离线收益是否超过在线主动操作」—— **这条必须做**（见 P0-1）
- ✅ 「测试主干/环路是否真的产生策略差异」—— 做主干时必须做
- ❌ 「测试不同生态地图」—— 还没有多生态地图，无对象可测

## 五、建议的执行顺序

按「能验证、依赖少、收益明确」排序：

**第 1 步：离线收益**（P0）
真缺口、改动小、有明确验证方法（离线 vs 在线收益对照）。

**第 2 步：自动化规则简化版**（P0）
在现有 `scoreCandidate` 加 2 个过滤条件，配 2 个 UI 开关。

**第 3 步：主干菌丝 + 汇流节点**（P1）
这一对是「让网络结构成为策略」的核心，做完后：
- 现有的「深耕 vs 铺广」变成三维取舍
- 菌株系统的「运输菌株」才有意义
- 平衡模拟能测出新的策略差异

**第 4 步：树木系统**（P1）
把 `root` 从资源格升级为「能影响周围」的生态节点。

**第 5 步：菌株 + 槽位**（P1）
此时才有 3~4 种真有差异的菌株可做（快速生长 / 运输 / 根系共生 / 腐木）。
**这一步做完，游戏的「Build 变化」才算成立** —— 也就是文档说的
「转生后的变化不再只是永久数值增加」。

**之后再说**：季节、地下层、多生态、菌落、图鉴。

---

## 六、一句话总结

**这份文档的「设计原则」（第二十二章）比它的「系统清单」有价值得多。**

19 个系统里，真正现在就该做的是 **2 个**（离线收益、自动化简化版），
值得接着做的是 **3 个**（主干、汇流、树木），
其余要么依赖未建成的系统，要么有过度设计风险，要么和现有设计重叠。

**核心判断：先做「让网络结构本身成为策略」的那一组（主干 + 汇流），
它是这份文档里唯一一个能同时提升多个既有系统价值的改动。**
